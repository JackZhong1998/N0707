## 1. SEO 是否需要每天做

SEO 是长期工作，但不意味着网站必须每天改、每天发文章或每天更新日期。

正确的长期循环是：

```text
发现需求与问题 → 选择最高价值动作 → 修改或发布 → 验证 → 等待有效数据 → 复盘与迭代
```

不同动作需要不同频率：

- **每天观察**：可用性、部署异常、索引事故、重要查询和转化异常。
- **每周优化**：已有页面、内链、搜索结果点击率、内容生产与发布。
- **每月审计**：索引覆盖、重复内容、技术健康、页面体验、内容衰退和主题集群。
- **每季度调整**：信息架构、品类定位、内容投资方向、国际化和大规模合并/清理。

小网站没有必要每天跑完整爬虫，也不应该因为“今天必须做 SEO”而制造一个低质量页面。Google 明确强调面向人的有用内容，并把大量自动生成、缺乏新增价值的内容视为危险信号。

## 2. 建站与上线基线

新网站上线前或接手网站的第一阶段，先建立可测量基线。

### 搜索可访问性

- 重要公开页面返回 200。
- 私有、登录、后台、筛选参数和重复 URL 不进入 sitemap。
- robots.txt 不误拦重要页面。
- 每个可索引页面输出正确 canonical。
- 多语言页面使用自指 canonical 与双向 hreflang。
- 移动端可以读取主要内容和完成主要转化。
- JavaScript 渲染不会隐藏标题、正文、链接或结构化数据。

### 页面与意图地图

建立一张表：

| URL | 页面类型 | 主要受众 | 主搜索意图 | 转化动作 | 索引状态 | 负责人 |
|---|---|---|---|---|---|---|

一个重要搜索意图只指定一个主要承接页。相似页面要区分意图，无法区分时应合并，避免内部竞争。

### 数据与工具

- 配置 Google Search Console 与 Bing Webmaster Tools。
- 配置产品分析或 Web Analytics，并定义 SEO 转化事件。
- 提交 sitemap，但不要把“已提交”误认为“保证收录”。
- 记录基线：有效公开页数、已索引页数、非品牌展现/点击、自然搜索转化和核心页面表现。

## 3. 运营节奏

### 每日：15–45 分钟

每日工作的目标是发现异常并选择动作，不是完成固定发文数量。

1. 检查生产站、关键页面和最近部署是否正常。
2. 查看 Search Console 24 小时或最近数据，仅用于发现事故、突增和突降；不要据此判断长期趋势。
3. 查看自然搜索转化是否出现明显异常。
4. 检查前一天修改是否正确上线、可抓取、无回归。
5. 从机会队列选择一个最高价值动作；没有可靠动作时只记录观察。

可执行的日任务示例：

- 修复一个错误 canonical 或 sitemap 条目。
- 改善一个高展现低 CTR 页面的 title/description。
- 为一个排名 8–30 的页面补充缺失答案与相关内链。
- 修复一个断链、重定向链或结构化数据错误。
- 将一份真实用户问题转化成现有页面的新章节。
- 验证新发布页面的渲染和索引信号。

### 每周：2–4 小时

1. 比较最近 28 天与前 28 天，并按查询、页面、国家、设备和品牌/非品牌拆分。
2. 维护机会队列：排名 8–30、高展现低 CTR、流量衰退、转化差和内容缺口。
3. 更新 1–2 个已有页面，或发布一个真正覆盖新意图的高质量页面。
4. 从相关高权重页面补充内链，并检查 anchor 是否自然明确。
5. 检查本周新增和更新 URL 的收录、抓取与结构化数据。
6. 复盘自然搜索带来的注册、咨询、购买或其他业务结果。

### 每月：半天到一天

1. 爬取所有公开可索引页面，检查状态码、canonical、noindex、标题、H1、重复内容、深度和孤岛页。
2. 检查 Page Indexing、sitemap、Core Web Vitals/PageSpeed 和 Rich Results。
3. 识别内容衰退、关键词互抢、旧事实、过期截图和无转化流量。
4. 合并或重写弱页面；不要只改发布日期。
5. 评估主题集群是否形成 Hub → 支持页 → 产品页的内链闭环。
6. 生成月报：业务结果、增长来源、损失来源、完成实验和下月优先级。

### 每季度：一到两天

1. 重新验证品类定位、ICP、市场与内容主题是否仍然一致。
2. 调整信息架构、导航和核心 Hub。
3. 审查需要合并、重定向、下线或 deindex 的 URL；批量动作必须人工批准。
4. 评估国际化、比较页、模板页或 programmatic SEO 是否有真实数据与独特价值支撑。
5. 将 SEO 投入与收入、销售线索、激活或留存连接，而不是只看流量。

## 4. 每日任务选择算法

按以下顺序处理，命中即优先：

### P0：事故

- 站点或重要页面 5xx/404。
- 误加 noindex、robots block 或错误 canonical。
- 部署后内容、CSS、导航或转化入口消失。
- 大量 URL 突然退出索引。

### P1：索引与重复问题

- 公开页未被发现或无法索引。
- 私有页、参数页、重复页进入 sitemap 或索引。
- hreflang、重定向、canonical 或 sitemap 互相冲突。

### P2：已有搜索需求

- 排名约 8–30 且有持续展现：补足意图、证据、章节和内链。
- 排名前 10 但 CTR 明显偏低：检查标题、描述和搜索结果承诺是否匹配。
- 历史表现页持续下降：检查内容过期、竞争变化、技术回归和意图漂移。

### P3：转化问题

- 查询相关但着陆页没有清晰下一步。
- CTA 与搜索意图不一致。
- 自然流量增长但注册、咨询或收入没有增长。

### P4：内容缺口

只有同时满足以下条件才创建新页面：

- 与产品、服务或受众直接相关；
- 现有页面没有承接该意图；
- 能提供原创经验、产品数据、方法、示例或更完整答案；
- 有合理内链入口和业务下一步；
- 不依赖批量生成薄内容。

## 5. 内容运营方法

每个页面至少明确：

- 一个主要问题或搜索意图；
- 一个清晰 H1；
- 第一屏直接答案；
- 完整解释、步骤、例子和限制；
- 可验证的作者/公司/产品经验；
- 相关内部链接；
- 与意图一致的 CTA；
- 准确的 title、description、canonical 和结构化数据。

更新旧内容时优先增加真实价值：新数据、实践经验、产品截图、方法变化、遗漏问题和更清晰结构。不要只换同义词、增加字数或更新日期。

## 6. 技术 SEO 方法

技术审计覆盖：

- HTTP 状态与重定向链；
- robots、noindex、canonical 与 sitemap；
- 多语言 alternate/hreflang；
- 标题、H1、描述和重复页面；
- JavaScript 渲染后的正文与链接；
- structured data 与页面可见事实一致性；
- 移动端体验、性能、可访问性和安全；
- 站内链接深度、孤岛页、分页与参数 URL；
- 图片、视频和其他搜索展示形式；
- 上线、更新和删除 URL 后的搜索引擎通知机制。

技术“通过”不等于页面会排名。它只保证搜索引擎可以正确发现、理解和评估内容。

## 7. 衡量与实验

### 业务指标

- 自然搜索转化、收入、有效线索、注册、激活或其他核心结果。
- 不同着陆页和查询类型带来的转化率。

### 搜索指标

- 非品牌点击与展现。
- 有效索引页占计划索引页的比例。
- 排名 8–30 的有效机会数。
- 高展现页面 CTR。
- 主题集群覆盖、内链和转化贡献。

### 评估窗口

- 事故和技术发布：当天验证。
- 抓取、索引和结构化数据：数天到数周。
- title/description 与 CTR：通常至少观察 2–4 周并控制查询变化。
- 内容与排名：通常以 4–12 周为主要评估窗口。
- 季节性业务：同比优先于简单环比。

一次只改变足够少的变量，并记录假设、修改时间、URL、指标和结论。不要把相关性直接当因果。

## 8. 自动化边界

### 适合自动化

- API/导出数据收集与清洗。
- 页面状态、canonical、robots、sitemap、hreflang 和 JSON-LD 检查。
- Search Console 机会排序和异常提醒。
- 小范围、可逆、可测试的代码或内容修复。
- 构建、类型检查、截图、报告和变更日志。
- 新增/更新/删除 URL 后的 IndexNow 通知（需明确授权和密钥）。

### 必须人工审核

- 品类定位与品牌承诺。
- 事实、客户案例、比较结论和 YMYL 内容。
- 批量生成、删除、合并、重定向或 deindex。
- 外部账号操作、URL 提交、发布、部署、commit 与 push。
- 可能导致大量 URL 或流量变化的架构调整。
